# Upstream v0.7.0 integration plan

> For agentic workers: use superpowers:executing-plans to complete this integration.

Goal: Merge upstream v0.7.0, cbb7bda137571bd255497787601618f3ff3e1f6f,
after committing the fork documentation, retaining the contracts in AGENTS.md.

Spec: [upstream update procedure](../../upstream-updates.md).

Architecture: Adopt upstream Desktop system-browser login and single-use code
redemption. Carry exact binding and callback/gate fingerprints in the handoff.
Carry optional credentials only as AES-GCM ciphertext under the external ring,
with a 120-second expiry. Create the native session and capture/fence credentials
only at redeem. Share the verified session completion path with web and mobile.
Keep the existing credential generation and tombstones as the sole lifecycle
authority. The handoff is temporary transport, not a second issuing store.

Tech stack: upstream Go 1.27.3, Mattermost SDK 0.6.0, go-jose 4.1.6,
Node 24, React/webpack, existing Go and Node test fixtures.

## Constraints

- Preserve exact issuer/subject/UUID and current native auth checks.
- No raw provider credentials or ID token in handoff KV, URLs, logs or responses.
- Optional credential/key failure may preserve ordinary login only after fencing.
- Authority/fence failure withholds completion and revokes only the new session.
- Preserve broker, management, web/mobile, and flat release archive contracts.
- Merge exactly the tag SHA. Do not integrate later upstream main or push.

- Lost keys or missing refresh tokens during a prepared capture must fence old credentials.

- Every native session path must run the same pre-create and post-capture checks.
